# final_recommendation_mart_v2 최종데이터 검토

## Executive Summary

- **판정: Needs revision — 현재 상태로는 프로젝트 최종데이터로 사용하면 안 됩니다.** 구조와 내부 산식은 정상이나, 팀이 합의한 최종 질문과 핵심 지표가 다릅니다.
- **가장 큰 문제는 종합 추천점수에 가격 방어력과 실제 3040 비중이 들어가지 않는다는 점입니다.** 방어력은 100개 행정동(23.9%)이 결측인데도 종합점수가 모두 계산되고, 전체 점수 상위 20곳 중 7곳도 방어력 결측입니다.
- **예산 필터도 실제 구매 후보 선정에 쓰기 어렵습니다.** 동일 자치구에서 행정동명과 법정동명이 정확히 같은 67개 사례를 진단 비교했을 때, v2의 전용 59㎡ 추정가와 2026년 실제 59㎡ 중앙가격의 절대 차이율 중앙값은 23.2%였습니다. 44곳은 20%를 넘었습니다.
- **v2는 행정동 탐색용 보조 피처 마트로는 활용할 수 있습니다.** 최종 후보표는 법정동×면적구간 기준의 실제 거래가격, 합의 통근지표, 하락기 낙폭, 3040 비중, 유동성, 신뢰도 플래그로 다시 고정하는 것이 안전합니다.

## 재현성 문제

현재 `run_comprehensive_analysis.py`는 다음 이유로 v2를 재생성하지 못합니다.

- 출력 파일명이 `final_recommendation_mart.csv`입니다.
- GBD·CBD·YBD를 핵심 행정동이 아닌 구 전체 코드 접두어로 정의합니다.
- 업무권역 내 통근시간을 이동량으로 재가중하지 않고 단순 평균합니다.
- 보고서에서 수정했다고 밝힌 교차검증 대신 학습 데이터 자체의 R²를 계산합니다.
- 가격 방어력 5개 열의 결합 코드가 없습니다.

명세서도 47개 열로 기록돼 있어 실제 v2의 52개 열과 일치하지 않습니다.

## 최종 사용 전 필수 수정

1. 최종 grain을 `법정동×면적구간`으로 고정합니다.
2. 예산은 실제 59㎡급·84㎡급 거래 중앙가격으로 필터링합니다.
3. 방어력은 `하락기_낙폭_%`과 `현재고점_미검증`, 유효분기 수를 함께 사용합니다.
4. 실제 `3040비중_%`과 유동성점수를 분리해 사용합니다.
5. 통근35·방어30·3040 25·유동성10을 기준안으로 재계산하고 민감도 분석을 합니다.
6. 두 사람 통근의 평균뿐 아니라 최대 통근시간도 추가합니다.
7. 결측 사유와 신뢰도를 점수와 분리해 표시합니다.
8. v2를 다시 만들 수 있는 단일 생성 스크립트와 52열 데이터 사전을 작성합니다.

## Caveats and assumptions

- 생활이동 OD에는 이동 목적이 없으므로 통근시간은 ‘출근 확정 시간’이 아니라 평일 아침 이동 대리지표입니다.
- 대안인 `05_candidate_master.csv`도 자동으로 최종 확정되는 것은 아닙니다. 1:N 매핑 한계, 방어력 결측·미검증, 가중치 민감도 검증이 남아 있습니다.
- 로컬 Python/Jupyter 실행기가 없어 검증 노트북은 만들지 못했습니다. 대신 실행 완료된 PowerShell 스크립트와 JSON 근거를 제공합니다.
- 표준 HTML 보고서 빌더에 필요한 Node.js가 없어 `report.html`은 생성하지 못했습니다. `artifact.json`은 향후 Node.js 환경에서 검증·패키징할 수 있도록 보존했습니다.
- 원본 CSV는 수정하지 않았습니다.
