서울시 상권 인구 데이터와 아파트 실거래가 235,098건(2021Q1–2026Q1)을
**법정동 단위**로 결합한 패널 데이터 구축 프로젝트.

분석 보고서: <https://claude.ai/code/artifact/70772bcb-bdd7-4fd7-8c44-d71ebdd789dd>

## 3. 실행 순서

```bash
python src/build_trdar_bjd_map.py    # 공간중첩 → trdar_bjd_fragments.csv
python src/build_panel.py            # 최종 패널 → panel_dong.csv, panel_gu.csv
```

2단계는 1단계 산출물에 의존하므로 순서를 지킬 것.
전체 소요 시간은 2~4분(`emd.shp` 57MB 중첩 연산이 대부분).

`data/output/`에 이미 결과가 들어 있으므로, **분석만 이어서 할 거면 실행할 필요 없다.**

## 5. ⚠️ 반드시 알아야 할 제약

분석 전에 이것부터 읽을 것. 모르고 쓰면 결과가 엉킨다.

1. **상주인구·직장인구는 연 1회만 갱신된다.**
   분기 파일이지만 21분기 동안 값이 3~5개뿐이다. 고정효과 패널에서 계수가 추정되지 않는다.
   유동인구(`길단위인구`)만 매 분기 실제로 변한다.

2. **`아파트_가구_수` 컬럼은 전부 0이다.** 원본이 그렇게 배포됐다. 사용 불가.

3. **실거래가 소스 경계는 계약분기 `20241`이다.**
   서울시 파일은 '접수연도' 기준이라 2024년 파일에 2023년 계약분이 섞여 있다.
   연도로 중복제거하면 국토부 2023년치 35,582건이 통째로 사라진다. 반드시 분기로 자를 것.

4. **상주인구 합계는 371만 명**으로 서울 실제 인구(약 940만)의 40% 수준이다.
   상권 반경 내 거주자만 집계하므로 전체 인구의 **대리 지표**로 이해할 것.

5. **단면 분석 결과는 상관관계이지 인과가 아니다.**

6. **macOS에서는 한글 파일명이 NFD로 저장된다.**
   `'아파트*.csv'`(NFC) 패턴이 NFD 파일명을 못 찾아 파일이 보이는데도
   `FileNotFoundError`가 난다. `paths.py`의 `find_one`/`find_all`이 양쪽을 NFC로
   정규화해 처리하므로, 새 스크립트에서도 `glob('한글*')`을 직접 쓰지 말고 이 함수를 쓸 것.
   자세한 내용은 [`data/raw/원본_데이터_안내.md`](data/raw/원본_데이터_안내.md).

## 7. 다음 단계

**→ [`ANALYSIS.md`](ANALYSIS.md) 를 볼 것.** 검증 결과·분석 기준·필요 데이터가 정리돼 있다.

한 줄 요약:

- 인구 **총량**은 가격을 설명하지 못한다(R²=0.024). 인구 **구성**이 설명한다.
- 거래량은 선행지표가 아니라 동행지표다(가격 관성 통제 시 p=0.973으로 소멸).
- 살아남은 변수는 **`log직주비`** (자치구 0.60 / 법정동 0.39, 양쪽 강건)와
  **`핵심생애주기비중`**(30대+40대).
- 다음 데이터 0순위는 **행안부 주민등록 인구통계**(법정동별 연령별 인구현황).
  현재 상주인구는 실제의 40%뿐이라 직주비 절대값이 1.8배 부풀려져 있고,
  21분기 동안 고유값이 3개라 **고정효과 추정이 아예 안 된다.** 월 단위 주민등록이 이 셋을 다 푼다.
- 그 다음은 **국민연금 가입 사업장 내역** — 법정동코드·업종·평균임금이 한 파일에 있다.
